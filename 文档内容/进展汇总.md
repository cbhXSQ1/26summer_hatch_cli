## 一、项目概述

Hatch 是一个 Python Coding Agent Harness。核心创新是用**客观的反馈信号**（pytest、flake8、mypy 输出）驱动 LLM 自我修正，而非依赖 LLM"自觉"。

### 技术栈

Python 3.10+ / Click CLI / httpx / YAML 配置 / keyring 凭据管理 / DeepSeek+GLM+Claude / prompt_toolkit TUI

## 四、本轮对话关键改动

### 1. 流式输出（commits `53c71e8` ← `52be18a`）

**改了什么**：
- `LLMBackend` 新增 `stream(messages) -> Generator[str]` 方法
- `OpenAICompatLLM.stream()` 用 SSE 协议（`stream: true`，逐行解析 `data:`）
- `MockLLM.stream()` 每 10 字符 yield 一块
- `AgentLoop` 用 `llm.stream()` 替代 `llm.complete()`，emit `stream_chunk` 事件
- CLI 实时打印每个 chunk（`click.echo(chunk, nl=False)`）

**效果**：LLM 回复逐字出现，不再等一次性返回。

### 2. 对话历史拼接（commit `7066b2a`）

**Bug 现象**：`run` 两次后 LLM 把两条用户消息当成一条（中间有 `\n\n`）

**根因**：工具调用成功后 `state.context_text` 没赋值 → `add_conversation_turn("assistant", ...)` 被跳过 → 对话历史缺少助手回复 → 连续两条 user 消息挨在一起

**修复**（commit `2243ccd`）：工具轮次也保存 LLM 自然语言部分到 `context_text`

### 3. 多次执行 bug（commit `133a2b1`）

**Bug 现象**：一次 `run` 执行两遍

**根因**：CLI `run()` 函数里有一段重复代码（lines 198-232 是 163-197 的完整拷贝），导致 `loop.run()` 被调用两次

### 4. System Prompt 重写（commit `651e849`）

**问题**：LLM 返回空 `[]` 时不输出文本

**修复**：Prompt 明确要求"不需要工具时，先写文本回复再放空 JSON 块，永远不要只输出 `[]`"

### 5. SessionManager 重构（commit `7066b2a`）

**改了什么**：去掉 `config.yaml` 活跃会话文件，改用 `get_latest()`（按 `updated` 排序取最新）。`run` 默认继续最新会话，`session new` 创建新会话。

### 6. 全面测试补充（commit `f32a2da`）

**160 → 247 测试**（+87 tests），覆盖：
- CLI 全命令（17 tests）
- 工具错误路径（13 tests）
- 反馈引擎分支（6 tests）
- 分类器/策略缺口（5 tests）
- Parser 缺口（3 tests）
- SessionMemory 缺口（6 tests）
- HITL/护栏/LLM/Loop 边界（11+5+6 tests）

## 五、关键设计决策

| 决策 | 理由 |
|------|------|
| 会话用 `get_latest()` 而非 `active_session` 文件 | 新终端默认继续最新对话，不引入额外状态文件 |
| 流式用 SSE 而非 WebSocket | OpenAPI 兼容的 SSE 更简单，httpx 原生支持 |
| 流式文本不加 `│ ` 装饰 | CJK 字符在 chunk 边界被切碎，且 LLM 回复本身有 markdown 格式 |
| system prompt 放在代码里而非配置文件 | prompt 应和代码逻辑紧密耦合，用户不需要改 |
| `key set` 用 `input()` 显示字符 | 不显示字符的密码输入在 API Key 场景无意义 |

## 七、TUI 交互界面（Phase 9）

`hatch chat [--cwd <dir>]` 启动 prompt_toolkit 交互界面：

```
[对话滚动区 — 流式输出逐步追加]
──────────────────────────────
> 你的输入...                              ← 固定输入栏（Tab 聚焦后 Enter 提交）
──────────────────────────────
目录  |  会话名  |  More  |  模型  |  key   ← 底部工具栏（Tab 循环聚焦）
```

| 按键 | 行为 |
|------|------|
| `Tab` / `Shift+Tab` | 底栏元素间循环切换焦点 |
| `Enter` | 提交输入 / 激活当前焦点元素 |
| `Esc` | 关闭下拉 / 取消重命名 |
| `↑/↓` | 下拉菜单内导航 |

| 焦点 | Enter 行为 |
|------|-----------|
| 会话名 | 内联重命名（输入框预填当前名，再 Enter 确认） |
| More | 下拉列出该目录所有会话，↑↓ 选 + Enter 切换 |
| 模型 | 下拉列出 provider/model，↑↓ 选 + Enter 热切换（同会话继续） |
| key | 显示已存凭据 provider 列表 |
| 输入栏 | 提交任务，流式输出逐步追加到对话区 |

首次回复后自动调用一次低温度（temperature=0.0）LLM 为会话命名。

## 八、运行时流程

```
用户运行: hatch run --cwd D:\project "修复 test.py"

1. CLI 解析 --cwd，os.chdir() 切换目录
2. SessionManager.get_latest_or_create() → 获取或创建会话
3. ConfigLoader.load("hatch.yaml") → 读取 LLM/工具配置
4. KeyManager.get_key() → 从系统凭据管理器读取 API Key
5. _build_llm() / _build_registry() → 构建 LLM 实例 + 工具注册表
6. AgentLoop.run() 启动主循环：
   ┌─ 第 1/N 轮 ─────
   │ 🧠 思考中...
   │ [流式输出 LLM 回复]
   │ 🔧 调用工具: file_reader  → ✅ 成功
   │ 🔧 调用工具: file_writer   → ✅ 成功
   │ 🔧 调用工具: test_runner   → ❌ 失败
   │ 📋 反馈: 1 个问题
   └─ 本轮未通过 → 继续
   ┌─ 第 2/N 轮 ─────
   │ [LLM 收到反馈，修正代码]
   │ 🔧 调用工具: test_runner   → ✅ 成功
   │ ✅ 反馈: 全部通过
   └─ 本轮通过 ✓
   🎉 任务成功完成 (2 轮)
7. SessionManager.save/add_conversation_turn → 持久化对话历史
```

## 九、CLI 命令一览

```powershell
# 核心
hatch run [--cwd <dir>] [--verbose/--quiet] <任务>   # 执行任务（默认流式详细输出）
hatch chat [--cwd <dir>]                 # 启动 TUI 交互界面（prompt_toolkit）

# 会话
hatch session list [--cwd <dir>]     # 列出所有对话（* 标记最新）
hatch session new  [--cwd <dir>]     # 新建对话
hatch session use  [--cwd <dir>] <id>  # 切换到指定对话
hatch session info [--cwd <dir>]     # 查看当前对话

# 凭据
hatch key set [--provider <name>]    # 录入 API Key（显示输入字符）
hatch key status                      # 查看状态
hatch key clear [--provider <name>]  # 清除
hatch key rotate [--provider <name>] # 替换

# 配置
hatch config show                    # 显示当前配置
hatch config validate                # 验证配置文件
```
